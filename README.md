# تخفیف‌یاب پیامکی (CuponApp)

اپلیکیشن اندرویدی که پیامک‌های گوشی را می‌خواند، پیام‌های شخصی و بانکی را
**روی خود گوشی** کنار می‌گذارد، و فقط پیامک‌های تبلیغاتی را به هوش مصنوعی
می‌سپارد تا کدهای تخفیف، مبلغ، شرایط و تاریخ انقضا از آن‌ها استخراج شود.

## دریافت خودکار

پیامک تازه که می‌رسد، اندروید گیرنده اپ را بیدار می‌کند — حتی اگر اپ بسته
باشد. همان فیلتر محلی همان‌جا اجرا می‌شود و اگر پیامک از آن عبور کرد، کد
تخفیفش استخراج و به صورت اعلان نشان داده می‌شود. از روی خود اعلان می‌توانید
کد را کپی کنید بدون آنکه اپ را باز کنید.

چون هنگام رسیدن پیامک WebView اجرا نمی‌شود، منطق فیلتر در `SmsClassifier.kt`
دوباره پیاده شده است. هر تغییری در `src/lib/smsFilter.ts` باید آنجا هم
اعمال شود، وگرنه رفتار اسکن دستی و دریافت خودکار از هم جدا می‌افتد.

## معماری

```
صندوق پیامک اندروید
        │  (SmsReaderPlugin.kt — مجوز READ_SMS)
        ▼
  فیلتر محلی (src/lib/smsFilter.ts)
        │   پیام شخصی / بانکی / رمز یک‌بارمصرف  ──►  حذف، هرگز ارسال نمی‌شود
        ▼
  فقط پیامک تبلیغاتی
        │  (src/lib/ai.ts — AvalAI، سازگار با OpenAI)
        ▼
  کدهای تخفیف ساختاریافته  ──►  رابط کاربری React
```

- **پوسته نیتیو:** Capacitor روی یک رابط کاربری React/Vite با پشتیبانی کامل RTL
- **خواندن پیامک:** پلاگین Kotlin در `android/app/src/main/java/com/cuponapp/smsdiscounts/SmsReaderPlugin.kt`
- **هوش مصنوعی:** تماس مستقیم از خود اپ با [AvalAI](https://avalai.ir)؛ بدون نیاز به سرور واسط

## حریم خصوصی

سه لایه محافظت، به ترتیب اجرا:

1. فقط صندوق **ورودی** خوانده می‌شود؛ پیامک‌های ارسالی و پیش‌نویس‌ها لمس نمی‌شوند.
2. فیلتر محلی پیش از هر تماس شبکه‌ای اجرا می‌شود و این موارد را حذف می‌کند:
   رمزهای یک‌بارمصرف و کد تایید، پیامک‌های بانکی و تراکنش مالی، و پیام‌های
   شخصی از شماره‌های موبایل.
3. پیامک‌های سرشماره‌ای که هیچ نشانه‌ی تخفیفی ندارند هم ارسال نمی‌شوند.

## کنترل هزینه

هر پیامکی که به هوش مصنوعی برود هزینه دارد، پس فیلتر با **امتیازدهی** کار
می‌کند، نه با یک قانون بله/خیر. هر نشانه در متن وزنی دارد — «تخفیف» و «کوپن»
وزن ۳، «جشنواره» و «۳۰٪» وزن ۲، «لینک» و «نام برند» وزن ۱ — و فقط پیامکی
ارسال می‌شود که مجموع وزنش از آستانه بگذرد.

سه سطح در تنظیمات قابل انتخاب است:

| سطح | آستانه | رفتار |
|---|---|---|
| آزاد | ۲ | هر نشانه متوسطی کافی است؛ کمترین احتمال از دست دادن تخفیف |
| **متعادل** | **۳** | یک نشانه قوی، یا دو نشانه متوسط — **پیش‌فرض** |
| سخت‌گیر | ۵ | نیاز به چند نشانه همزمان؛ کمترین هزینه |

دو صرفه‌جویی دیگر:

- **حذف تکراری‌ها:** پیامک‌های تبلیغاتی اغلب چند بار فرستاده می‌شوند. متن‌هایی
  که فقط در اعداد فرق دارند یک اثر انگشت می‌گیرند و یک‌بار تحلیل می‌شوند.
- **کش بین اسکن‌ها:** هر پیامکی که یک‌بار تحلیل شد در اسکن‌های بعدی رد
  می‌شود. از تنظیمات قابل پاک کردن است.

روی نمونه‌های واقعی فارسی، از هر ۱۸ پیامک صندوق ورودی حدود ۷ مورد به هوش
مصنوعی می‌رسد.

کلید API فقط در حافظه خصوصی اپ روی گوشی ذخیره می‌شود و در مخزن کد یا داخل
فایل APK قرار ندارد.

## انتخاب مدل

مدل پیش‌فرض `gemini-2.5-flash-lite` است: ارزان‌ترین گزینه‌ای که هم فارسی را
خوب می‌فهمد و هم خروجی JSON ساختاریافته می‌دهد — دقیقاً چیزی که این کار
نیاز دارد. از صفحه تنظیمات می‌توانید فهرست مدل‌های حساب خود را بگیرید و
بدون بیلد مجدد مدل را عوض کنید.

هزینه تقریبی: هر اسکن کامل ۲ ماه پیامک معمولاً چند ده هزار توکن است، یعنی
کسری از یک سنت.

## بروزرسانی خودکار

هر push روی برنچ، یک نسخه تازه با شماره بالاتر (`1.0.<شماره بیلد>`) منتشر
می‌کند. اپ هر بار که باز شود آخرین نسخه را از گیت‌هاب می‌پرسد و اگر جدیدتر
بود، نواری بالای صفحه نشان می‌دهد که با یک ضربه APK را دانلود و نصب می‌کند.
داده‌های قبلی (کدها و تنظیمات) حفظ می‌مانند.

> اندروید به یک اپ معمولی اجازه نمی‌دهد خودش را بی‌صدا جایگزین کند، پس نصب
> نهایی همیشه یک ضربه تأیید از کاربر می‌خواهد.

اگر مخزن **خصوصی** باشد، گیت‌هاب اجازه بررسی بی‌نام نمی‌دهد. دو راه دارید:
مخزن را عمومی کنید، یا یک توکن فقط-خواندنی گیت‌هاب در تنظیمات اپ وارد کنید.

## نصب روی گوشی

فایل APK از بخش [Releases](../../releases/latest) قابل دانلود است.

پس از نصب:

1. مجوز «خواندن پیامک» را بدهید.
2. از دکمه تنظیمات (گوشه پایین-چپ) کلید API اول‌ای‌آی خود را وارد کنید و
   «تست اتصال» را بزنید.
3. دکمه «اسکن پیامک‌ها و استخراج تخفیف‌ها» را بزنید.

## کلید امضا — لازم برای بروزرسانی

اندروید اجازه نمی‌دهد اپی که با یک کلید امضا شده، با APK ای که کلید دیگری
دارد جایگزین شود. بدون یک کلید ثابت، هر بیلد امضای متفاوتی می‌گیرد و نصب
روی نسخه قبلی با خطای «App not installed» شکست می‌خورد.

یک بار کلید بسازید:

```bash
keytool -genkeypair -v \
  -keystore cuponapp-release.keystore \
  -alias cuponapp \
  -keyalg RSA -keysize 4096 -validity 10950 \
  -dname "CN=CuponApp, O=CuponApp, C=IR"
```

سپس آن را به base64 تبدیل کنید:

```bash
base64 -w0 cuponapp-release.keystore
```

و این چهار مقدار را در `Settings → Secrets and variables → Actions` مخزن
ثبت کنید:

| نام Secret | مقدار |
|---|---|
| `KEYSTORE_BASE64` | خروجی دستور base64 بالا |
| `KEYSTORE_PASSWORD` | رمزی که هنگام ساخت وارد کردید |
| `KEY_PASSWORD` | همان رمز (مگر جدا تعیین کرده باشید) |
| `KEY_ALIAS` | `cuponapp` |

> فایل `cuponapp-release.keystore` را جایی امن نگه دارید و **هرگز کامیت نکنید**.
> اگر گم شود، دیگر نمی‌توانید نسخه‌های بعدی را روی نصب فعلی بروزرسانی کنید.

اگر این Secretها تنظیم نشده باشند، بیلد شکست نمی‌خورد ولی با کلید موقت
امضا می‌شود و در لاگ هشدار می‌دهد.

## توسعه

```bash
bun install

# اجرای نسخه وب (بدون دسترسی به پیامک)
bun run dev

# ساخت پروژه اندروید
bun run android:sync
cd android && ./gradlew assembleRelease
```

خروجی: `android/app/build/outputs/apk/release/app-release.apk`

هر push روی هر شاخه، گردش‌کار `.github/workflows/android-build.yml` را اجرا
می‌کند که APK را می‌سازد و روی تگ `latest` منتشر می‌کند.

## محدودیت‌ها

- مجوز `READ_SMS` در Google Play بسیار محدود است؛ این اپ برای نصب مستقیم
  (sideload) طراحی شده، نه انتشار در فروشگاه.
- اپ برای تحلیل به اینترنت نیاز دارد. اگر هنگام رسیدن پیامک آفلاین باشید،
  آن پیامک در اسکن دستی بعدی بررسی می‌شود.
